# B800-069 — Per-database state evidence and Database Health wiring

**Umbrella:** #287  
**PR:** #288  
**State:** IN VALIDATION

## Objective

Close the gap between the aggregate database-state counts and the existing B300 database-state classifier without reconstructing exact database states from the lossy `OfflineOrOther` aggregate.

## Implemented

- Extended `DatabaseHealthDetailSnapshot` with an optional bounded `Items` collection of logical database name + `state_desc`.
- Appended `DatabaseStatesJson` to the existing one-statement bounded monitored-SQL snapshot query.
- Collector retains at most 50 **user database** rows (`database_id > 4`) and orders non-online rows before online rows.
- No table data, physical file path, SQL text or query plan is selected.
- Added fail-closed validation for row count, logical name and state text before snapshot publication.
- Added `DatabaseStateProjection` that reuses B300 normalization/classification/actionable/worst rules over the retained exact rows.
- Reworked `/database-health` to expose bounded per-database state evidence, actionable classification and worst-observed state while preserving aggregate server counts and cache-only GET behavior.
- The UI explicitly labels this as bounded retained evidence, not an unbounded catalog browser or a claim that omitted online rows were inspected on page load.
