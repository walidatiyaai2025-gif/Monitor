# B800-067 — Bounded HA readiness evidence

**Umbrella:** #287  
**State:** IMPLEMENTED / VALIDATION PENDING

## Objective

Add bounded, read-only Always On availability-group evidence to collected server snapshots without turning partial/local DMV state into a false quorum, RPO, RTO or failover-readiness claim.

## Evidence contract

Collection retains:

- explicit `IsHadrEnabled` state;
- total availability-replica metadata count and up to 16 risk-prioritized replica rows;
- availability group and replica logical names;
- availability/failover modes;
- local/role/connected/operational/synchronization-health state where the local SQL Server perspective exposes it;
- total database-replica state count and up to 64 risk-prioritized database-replica rows;
- database synchronization state/health, suspension state/reason;
- log-send queue KB, redo queue KB and `secondary_lag_seconds` when exposed by SQL Server.

Retained row counts must equal `min(total, bound)`. Truncation flags are true only when the corresponding server-side total exceeds the retained bound.

## Collection path

HA evidence is optional enrichment during the existing snapshot collection/refresh path. Browser GET/`Peek` remains cache-only. Query timeout, permission failure, invalid evidence or JSON failure leaves `Ha = null` while preserving the core snapshot and independent evidence dimensions.

## Truth boundary

This task does **not** claim or calculate:

- quorum health or cluster vote safety;
- RPO compliance against a policy;
- RTO readiness;
- failover readiness;
- automatic failover recommendation;
- B400 composite HA score/severity.

`secondary_lag_seconds` is retained as SQL Server-reported lag evidence only. Policy-backed RPO and quorum evidence must exist before `Batch400HaReadiness.Summarize` can be used truthfully.

## Privacy and safety

- no HADR endpoint URL;
- no cluster-node/member/vote identity;
- no SQL text, query plan, login/session/client identity or table data;
- no ALTER AVAILABILITY GROUP, failover, resume/suspend or other write/remediation action;
- max 16 replica rows + 64 database-replica rows;
- two-second command timeout and collection-only enrichment;
- no RC.61 or `#162 -> #116 -> #111` change.

## Validation

Required before merge on one exact final SHA:

- CI Green;
- Real SQL Server 2022 acceptance Green under monitored least privilege (including truthful non-HA behavior on the current acceptance target);
- Windows production-candidate Green;
- branch current with `main` and no unresolved review threads.

A positive multi-replica AG integration estate is not created by this slice; positive HA mapping/contract behavior is covered by deterministic tests until such an estate is available.
