# B800-067 — Bounded HA evidence

**Umbrella:** #287  
**State:** IMPLEMENTED / EXACT-HEAD VALIDATION PENDING

## Objective

Add bounded, privacy-safe Always On availability-group evidence to collected snapshots without converting topology/runtime observations into an unsupported failover-readiness or RPO claim.

## Evidence contract

The optional HA enrichment retains:

- `SERVERPROPERTY('IsHadrEnabled')` as the explicit feature-state flag;
- total local database-replica count;
- up to 50 local database replicas, prioritizing non-synchronized/unhealthy/high-queue rows;
- logical availability-group and database identity only;
- local replica role, synchronization state and synchronization health;
- connected state when reported;
- automatic-failover configuration flag and suspension state;
- send/redo queue bytes and secondary lag seconds when reported;
- quorum state plus aggregate healthy/total vote counts when cluster evidence is available.

Replica endpoint URLs, remote replica server names and cluster member names are deliberately excluded.

## Collection path

HA evidence is an optional enrichment performed only during the existing snapshot collection/refresh path. Browser GET/`Peek` remains cache-only and never starts monitored SQL work. Timeout, permission, invalid-row or decode failure leaves the core snapshot intact with `HighAvailability = null`.

A SQL instance with HADR disabled is represented explicitly as `IsHadrEnabled=false`, zero local database replicas and no synthetic health/readiness conclusion.

## Truth boundary

This task does **not** calculate or display:

- `FailoverReady`;
- `RpoCompliant`;
- `RtoReady`;
- quorum-risk severity or a B400 composite HA score;
- a configured maximum RPO lag.

Those conclusions require policy and complete runtime/quorum evidence. Missing evidence is never treated as healthy.

## Privacy and safety

- no endpoint URLs, cluster member names or remote replica server names;
- no SQL text, query plans, session/client identity or table data;
- no failover, suspend/resume, routing, endpoint or cluster mutation;
- query remains read-only, max 50 replica rows and two-second command timeout;
- no browser-to-SQL path and no change to RC.61 or `#162 -> #116 -> #111`.

## Validation gate

Normal CI, SQL Server 2022 Real SQL acceptance under the monitored least-privilege login and Windows production-candidate must pass on one exact final head before this slice is marked verified. Issue #287 remains open.
