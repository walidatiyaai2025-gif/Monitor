# B800-083 — Bounded cached Server Intelligence export

## Scope

Expose the Server Details B300 intelligence already visible to operators as one contextual Viewer+ CSV without creating a new evidence source or monitored-SQL browser path.

## Runtime path

`GET /reports/server-intelligence/{registrationId:guid}.csv`

`EnterpriseReportsController -> IMonitorReadService.GetServerAsync -> cached ServerDetailsViewModel -> ServerIntelligenceProjection.Build -> ServerIntelligenceExport -> EnterpriseReportContract.Csv`

The route inherits `Monitor.Read`. `IMonitorReadService.GetServerAsync` resolves registration metadata and peeks the existing snapshot cache; the GET does not invoke a monitored-SQL query or collector.

## Export contract

- schema remains `monitor-export-v2`;
- existing 1000-row, 1-MiB and 500-char-cell bounds apply;
- existing CSV formula-safety applies to every emitted cell;
- central secure download headers and bounded filename policy apply;
- rows expose evidence state/time, safe B300 estate classification, cached runtime-pressure summary and bounded aggregate database/memory/blocking/performance evidence;
- the export reuses `ServerIntelligenceProjection.Build(model)`, so it does not invent a second classification or pressure algorithm.

## Truth boundary

When a registration exists but no cached snapshot is available, snapshot-derived fields are emitted as `Unavailable`. Database totals are not serialized as zero merely because the unavailable ServerCard placeholder carries zero-valued display fields. Runtime pressure remains `Unavailable` when its required cached evidence cannot be evaluated.

A complete cached snapshot may truthfully emit observed numeric zeroes. Stale evidence remains stale through the same `ServerIntelligenceProjection` evidence-state owner used by Server Details.

## Sensitive-data boundary

The report does not add or expose credentials, connection strings, SQL text, query plans, client identity, table data, raw provider errors or physical filesystem paths. No mutation, remediation, refresh, failover, maintenance action or SQL execution is available from the export path.

## Discoverability

Reports & Diagnostics contains a contextual Server Intelligence card and sends the operator through the existing Servers selection workflow before the registration-scoped export is used.

## Regression ownership

`tests/Monitor.Web.Tests/B800ServerIntelligenceExportTests.cs` verifies:

- `monitor-export-v2` and spreadsheet-formula protection;
- explicit unavailable snapshot/database/runtime-pressure truth;
- fresh projection parity with `ServerIntelligenceProjection`;
- Viewer/Read authorization;
- bounded filename behavior;
- controller/export source boundaries contain no monitored-SQL query or collector dependency and the read service uses cache `Peek`.
