# B800-030 — Workflow closeout regression gate

## Goal

Close the first BATCH-800 workflow-hardening sequence without adding a new product capability. This task binds the already-implemented B800-021..029 contracts into one regression gate so later work cannot silently remove a covered workflow boundary while individual tests still drift independently.

## Contract

The closeout test requires all nine workflow regression suites introduced by B800-021..029 to remain present and executable:

- protected POST authorization + antiforgery matrix;
- Razor POST form -> real controller POST endpoint wiring;
- bounded GET filters/paging/navigation;
- PRG + explicit conflict/not-found/validation outcomes;
- incident/AI Advisor role-visible mutation controls;
- Connection Lab test-before-save/write-only-secret workflow;
- Administrator Settings backup/restore workflow;
- Governance retention destructive confirmation;
- Enterprise Operations Read/Manage/Operate role wiring.

It also locks the two explicit destructive confirmation tokens already used by the product:

- `RESTORE` for operational restore;
- `PRUNE` for retention apply.

Views that render those confirmation tokens must remain POST forms. Existing B800-021 authorization/antiforgery coverage remains authoritative for endpoint policy checks; B800-030 does not duplicate or weaken it.

## Safety boundary

- test/docs only;
- no runtime/controller/service/collector behavior change;
- no monitored SQL;
- no permission change;
- no autonomous remediation or AI SQL execution;
- no selected RC.61/tag/release mutation;
- no production IIS/SQL mutation and no #162/#116/#111 implication.

## Acceptance

- `B800WorkflowCloseoutTests` passes together with the existing B800-021..029 regression suites;
- normal CI is Green on the exact PR head;
- branch remains current with `main` before merge;
- B800-030 closes only the workflow-hardening sequence. Issue #287 remains OPEN for B800-064..068, B800-070+ and later work.
