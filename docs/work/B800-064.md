# B800-064 — Policy-backed backup RPO configuration

**Umbrella:** #287  
**Branch:** `agent/b800-backup-rpo-policy`  
**State:** IMPLEMENTED / EXACT-HEAD VALIDATION PENDING

## Objective

Add an explicit operator-configured backup RPO policy without inventing default Full/Log RPO values and without claiming B300 backup compliance from evidence that the current snapshot does not collect.

## Implementation

- Added `BackupPolicyOptions` under configuration section `BackupPolicy`.
- Policy is disabled by default; base and production example configuration contain no Full/Log RPO numeric defaults.
- When `Enabled=true`, both positive `FullRpoMinutes` and `LogRpoMinutes` are required; incomplete or non-positive configuration fails validation.
- Startup binds, validates and registers one `BackupPolicyOptions` singleton.
- The cached Backups page receives the validated policy through `OperationsController` and displays configured Full/Log RPO metadata when present.
- The page always reports B300 compliance as `Not evaluated` because the current cached snapshot lacks per-database recovery model and last log-backup timestamps.
- Existing 24-hour full-backup aggregate evidence remains visible but is never reinterpreted as policy compliance.

## Truth boundary

`Batch300BackupCompliance.Evaluate` is deliberately not invoked by this slice. The B300 helper requires per-database recovery model, last full backup and last log backup. B800-064 supplies the missing policy contract only; a later evidence-backed slice must collect the remaining database-level facts before any compliant/non-compliant classification is shown.

## Safety boundary

No new monitored-SQL query or permission is added. Browser GET stays cache/control-plane only. No backup operation, credential, production IIS/SQL state or RC.61 state is changed.
