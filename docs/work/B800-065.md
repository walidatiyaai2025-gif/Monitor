# B800-065 — Bounded TempDB evidence

**Umbrella:** #287  
**State:** IMPLEMENTED / EXACT-HEAD VALIDATION PENDING

## Objective

Add truthful bounded TempDB evidence to collected server snapshots without inventing interval growth or allocation-contention conclusions that the current snapshot history does not support.

## Evidence contract

Collection retains point-in-time / cumulative evidence only:

- logical CPU count;
- total TempDB data-file count;
- up to 32 TempDB data files ordered by file id;
- logical file id and logical file name only;
- current allocated size bytes;
- current used bytes when `dm_db_file_space_usage` evidence is available;
- cumulative reads/writes and read/write stall milliseconds from `sys.dm_io_virtual_file_stats`.

`TempDbHealthSnapshot.IsTruncated` is true when the server has more TempDB data files than the bounded retained list.

## Collection path

TempDB evidence is an optional enrichment performed only during the existing snapshot collection/refresh path. Browser GET/`Peek` remains cache-only and never starts monitored SQL work. If the optional TempDB query times out, lacks permission, returns invalid evidence or cannot be decoded, the core server snapshot is retained with `TempDb = null` rather than converting missing evidence to zero/healthy or failing unrelated monitoring dimensions.

## Truth boundary

This task does **not** calculate or display:

- TempDB growth per hour;
- interval allocation pressure;
- PFS/GAM/SGAM contention scores;
- historical file-growth trend;
- a healthy/unhealthy classification from missing evidence.

Those require explicit interval/history evidence before B400 TempDB functions can be evaluated truthfully.

## Privacy and safety

- no `physical_name` or filesystem path;
- no SQL text, query plan, client identity or table data;
- no configuration write, file resize or autonomous remediation;
- query remains read-only, max 32 rows, two-second command timeout;
- no browser-to-SQL path and no change to RC.61 or `#162 -> #116 -> #111`.

## Validation gate

Normal CI, Real SQL acceptance and Windows production-candidate must pass on one exact final head before this task is marked verified. Any required permission change must be the narrowest read-only grant proven necessary by Real SQL validation. Issue #287 remains open.
