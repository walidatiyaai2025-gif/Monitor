# B800-020 — Governed snapshot runtime parity

**Umbrella:** #287  
**State:** IMPLEMENTED / EXACT-HEAD VALIDATION PENDING

## Objective

Close the runtime-path validation gap between the extended `SqlSnapshotQuery.CommandText` evidence contract and the `GovernedSqlSnapshotQuery` implementation actually registered in production DI.

## Defect found

The shared SQL command had already added extended memory evidence plus bounded wait, logical-file I/O, SQL Agent run/activity and per-database state JSON columns. The direct `SqlSnapshotQuery` reader mapped ordinals 34..45, but `GovernedSqlSnapshotQuery` stopped at ordinal 33. Because `Program.cs` registers `ISqlSnapshotQuery` as `GovernedSqlSnapshotQuery`, the governed runtime path discarded that extended evidence even though the SQL command returned it.

## Correction

`GovernedSqlSnapshotQuery` now maps the same extended columns as the direct query:

- memory diagnostics at ordinals 34..40;
- bounded wait evidence at ordinal 41;
- bounded logical-file I/O evidence at ordinal 42;
- bounded SQL Agent run history at ordinal 43;
- bounded per-database state evidence at ordinal 44;
- bounded current SQL Agent schedule/activity evidence at ordinal 45.

JSON deserialization remains typed and bounded by the existing collector validation. The governed query continues to use the exact shared `SqlSnapshotQuery.CommandText`, the existing two-second command timeout and `PerformanceScaleOptions` connection governance.

## Safety boundary

This task adds no new monitored-SQL query, permission, browser SQL path, credential surface, production mutation, remediation or RC.61 change. It restores already-approved evidence to the runtime DI path. Existing caps, validation and privacy exclusions remain unchanged.

## Validation gate

Normal CI and applicable Real SQL acceptance must pass on one exact final head before this task is marked verified. Issue #287 remains open.
