# B800-072 — Maintenance safety decision support

**Umbrella:** #287  
**State:** IMPLEMENTED / VALIDATION PENDING

## Objective

Expose the existing B400 maintenance-safety contract as read-only operator decision support without fabricating approval, rollback, approved-window, replica-readiness, or recent-backup evidence that Monitor does not currently own.

## Evidence model

`MaintenanceDecisionEvidence` distinguishes direct observed facts from governed inputs that may be unavailable:

- selected maintenance operation;
- production/non-production environment classification;
- observed configured maintenance-window activity;
- approved-window evidence (`bool?`);
- approval evidence (`bool?`);
- rollback-plan evidence (`bool?`);
- active critical incident count (`int?`);
- replica-health evidence (`bool?`);
- recent-backup evidence (`bool?`).

A configured operator maintenance window is retained as `ObservedMaintenanceWindowActive` only. It is **not** promoted to `InApprovedWindow` because the current metadata model has no independent approval field.

## Required-input gating

`MaintenanceDecisionSupport` first asks the existing `Batch400MaintenanceSafety` helper which inputs are actually required for the selected operation/environment:

- approval when B400 says approval is required;
- rollback plan when B400 says rollback is required;
- approved window when B400 says a window is required;
- replica health for failover;
- recent backup for restore/patch;
- active critical incident count for every evaluated operation.

If any required input is unavailable, status is `NotEvaluated`, `Decision = null`, and the missing input names are surfaced. Missing evidence is never defaulted into a pass/fail decision.

Only after every relevant input is present does the wrapper construct `MaintenanceContext` and delegate to `Batch400MaintenanceSafety.Decide`.

## Current repository wiring

The read-only controller `/enterprise/maintenance/{serverId}` uses only:

- enabled server registration;
- server environment and configured maintenance-window metadata;
- current open critical incident count.

The repository currently has no governed approval, rollback-plan, approved-window, replica-readiness, or policy-backed recent-backup source for this page, so those fields remain `null`.

Consequences:

- many production operations are correctly `NotEvaluated` until governed inputs exist;
- some low-risk non-production operations can be evaluated when their only relevant live blocker is the observed critical-incident count;
- a configured maintenance window alone can never unlock an approved-window requirement.

## Operator surface

Enterprise Operations now links each server to **Maintenance decision support**.

The page:

- is protected by `Monitor.Read`;
- contains a GET-only operation selector;
- shows environment, configured-window activity, open critical incidents, and the selected operation;
- displays `Ready`, `Blocked`, or `NotEvaluated`;
- lists missing governed evidence when not evaluated;
- displays B400 risk/requirements/blockers only when a decision was actually evaluated;
- contains explicit `DECISION SUPPORT ONLY` and `No action executed` wording.

## Safety boundary

- no POST endpoint or execute button;
- no maintenance command, failover, restore, patch, configuration mutation, index/statistics execution, or backup execution;
- no monitored SQL query or cache refresh;
- no notification or pager path;
- no approval/rollback/readiness claim from absent data;
- no RC.61 or `#162 -> #116 -> #111` change.
