# B800-073 — Bounded incident decision evidence

Umbrella: #287

## Purpose

B800-071 fleet correlation/routing and B800-072 maintenance safety decision support both consumed the legacy `IHealthIncidentRepository.GetAll()` result directly. That made operator decision inputs implicitly unbounded and created a truth risk: simply taking a subset later could make a partial incident set look complete.

B800-073 centralizes the operator decision boundary in `BoundedIncidentReadModel`.

## Contract

- Only active (`!= Resolved`) incidents for the requested registration set are admitted.
- The default decision-input bound is 100, matching the existing `PerformanceScaleOptions.IncidentMaxPageSize` default.
- The projection reads at most `limit + 1` rows after scope/filter ordering so it can distinguish complete evidence from overflow.
- Overflow is explicit through `IsComplete=false` / `IsTruncated=true`; the retained subset must never be treated as a complete incident population.
- Empty registration scope returns complete empty evidence without reading the incident store.
- Limits outside 1..1000 fail closed.

## Fleet behavior

- Fleet Intelligence uses bounded active incidents for enabled registered servers.
- When evidence is complete, existing B400 correlation, B300 routing recommendations and rule hot-spots behave as before.
- When evidence exceeds the bound, correlation/routing and rule hot-spots are withheld rather than computed from a partial incident set.
- The UI explicitly says decision support is not evaluated and explains the bound.
- No notification, pager, incident mutation, suppression action or remediation is added.

## Maintenance behavior

- Maintenance Decision Support uses the same bounded server-scoped projection.
- When incident evidence is complete, the exact open Critical incident count is supplied to the existing B800-072/B400 decision wrapper.
- When evidence overflows, `ActiveCriticalIncidents` becomes unavailable (`null`), so `active-critical-incidents` remains a missing input and the maintenance result is `NotEvaluated`.
- The UI renders `Not evaluated`; it never substitutes zero.

## Storage boundary / follow-up

`IHealthIncidentRepository.GetAll()` remains a legacy storage API in this slice. B800-073 bounds and truthfully classifies **operator decision inputs**; it does not claim that File/Shared/InMemory storage materialization is now server-query-bounded. A later storage-focused task may add server-scoped/paged repository queries underneath this read-model contract without changing Fleet/Maintenance truth semantics.

This deliberate boundary avoids widening B800-073 across File, Shared, Telemetry and backup/restore incident-store implementations before that storage contract is reviewed coherently.
