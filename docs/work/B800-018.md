## Objective

Lock the Server Details read/mutation boundary with regression coverage so a future UI/controller refactor cannot silently expose refresh controls to read-only users or weaken the protected refresh endpoint.

## Contract covered

- `GET /servers/{id}` inherits the controller-level `MonitorPolicies.Read` authorization boundary.
- Server Details GET reads the cached `IMonitorReadService.GetServerAsync` path and does not call snapshot refresh or monitored-SQL collector code.
- `POST /servers/{id:guid}/refresh` remains protected by `MonitorPolicies.Operate` plus `ValidateAntiForgeryToken`.
- Server Details renders refresh forms only inside the existing Administrator/Operator role gates.
- Connection Lab recovery navigation remains Administrator-only.
- Reader-specific mutation UI is not introduced.
- The view keeps the explicit cache-only GET / protected POST wording and contains no SQL execution surface.

## Regression evidence

## Safety boundary

Test/documentation-only slice. No runtime behavior, production IIS/SQL state, selected RC.61 state, credentials, connection strings or collector permissions are changed.
