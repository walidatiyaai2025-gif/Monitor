# B800-071 — Fleet correlation and routing decision support

**Umbrella:** #287  
**State:** IMPLEMENTED / VALIDATION PENDING

## Objective

Wire the existing B400 fleet-correlation and B300 alert-routing contracts into Fleet Intelligence as bounded, deterministic **decision support only**. The feature must not send notifications, page an operator, mutate incident state, execute maintenance, or trigger remediation.

## Inputs

Only current repository evidence is used:

- open, non-resolved incidents;
- incident rule/severity/last-seen time;
- registered server environment classification;
- active alert-suppression state;
- active maintenance-window state;
- optional incident assignee.

Incidents without a matching enabled registered server are excluded from route/correlation suggestions rather than receiving guessed environment or policy state.

## Correlation

`FleetDecisionSupport` maps `FindingSeverity` to the existing B400 severity classes and delegates grouping/scoring to `Batch400FleetCorrelation`.

- correlation window uses the helper's bounded default (`ClampWindow(TimeSpan.Zero)` = five minutes);
- group key remains environment + rule + time bucket through the existing opaque correlation key;
- affected-server blast radius, environment list, dominant rule, severity and score come from B400;
- output is capped at 20 clusters.

The score is displayed as correlation evidence only. It does not trigger routing, suppression, failover or remediation.

## Routing recommendation

For at most 20 current incidents, `FleetDecisionSupport` delegates to `Batch300AlertRouting.Decide` using:

- environment from server operator metadata;
- severity score from `Batch400FleetCorrelation.SeverityWeight`;
- active suppression and maintenance state;
- optional assignee.

The result is stored/rendered as `SuggestedRoute`. Suppression or maintenance returns the existing B300 `AlertRoute.None` decision. The Fleet page never invokes a sender, webhook, SMTP path, pager integration or mutation endpoint.

## Operator surface

Fleet Intelligence now includes:

- bounded open-incident correlation clusters;
- bounded suggested route/tier/cooldown/owner/reason rows;
- explicit `RECOMMENDATION ONLY` and `No notification is sent` wording.

The surface remains cache/metadata/incident read-only. No POST form is added.

## Fail-closed behavior

- malformed incident identity/rule input is excluded from decision-support calculation;
- missing incident assignee metadata falls back to the existing unassigned owner behavior;
- shared-state unavailability while reading optional assignee metadata does not create a route owner or fail the page;
- incidents with no matching enabled registered server do not receive guessed environment, suppression or maintenance policy.

## Safety boundary

- no notification/page/send action;
- no automatic suppression or incident transition;
- no maintenance execution;
- no monitored SQL query added;
- no SQL text, query plan, credential, connection string, session/login/client identity or table data exposed;
- no RC.61 or `#162 -> #116 -> #111` change.
