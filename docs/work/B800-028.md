# B800-028 — Governance retention destructive confirmation

**Umbrella:** #287  
**Branch:** `agent/b800-functional-screen-wiring`  
**PR:** #288  
**State:** IMPLEMENTED / EXACT-HEAD VALIDATION PENDING

## Objective

Close the destructive-confirmation gap in Administrator retention governance while preserving dry-run-first behavior and bounded audit receipts.

## Fix

- `GET /governance/retention` remains a read-only dry run over Monitor-owned control-plane state.
- `POST /governance/retention/apply` remains `MonitorPolicies.Manage` + antiforgery protected and now requires exact typed `PRUNE` confirmation before `_governance.Apply` is called.
- Missing/incorrect confirmation fails closed, writes a `governance.cleanup` / `confirmation-rejected` audit event, sets safe feedback and redirects without pruning.
- The Razor apply form now requires the five-character confirmation and explicitly distinguishes dry run from the destructive apply step.
- Successful apply still delegates to `GovernanceRetentionService`, which recalculates the current bounded dry-run plan and writes per-candidate prune receipts plus the cleanup summary receipt.

## Regression evidence

Added `tests/Monitor.Web.Tests/B800GovernanceRetentionWorkflowTests.cs` covering authorization/antiforgery, typed confirmation, rejection audit, dry-run/apply UI separation and bounded receipt behavior.

## Safety boundary

No monitored SQL target is contacted by this workflow, no production IIS/SQL state or RC.61 state is touched, and no retention candidate semantics are broadened. The change only adds a fail-closed human confirmation before an existing destructive control-plane action.

## Validation gate

Exact-head normal CI must pass, including any existing Governance tests updated to supply the newly required confirmation where they intentionally exercise successful apply.
