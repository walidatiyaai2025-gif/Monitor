# B800-063 — Bounded SQL Agent schedule activity evidence

**Umbrella:** #287  
**PR:** #288  
**State:** IN VALIDATION

## Objective

Add bounded current SQL Server Agent schedule/activity evidence before any lateness function is enabled. The task must not infer late/on-time state from schedule metadata whose time-zone and recurrence semantics are not explicitly represented in the snapshot.

## Evidence contract

The existing one-statement snapshot collector now appends one optional `AgentSchedulesJson` column at ordinal 45, preserving all existing evidence ordinals.

For the current SQL Agent activity session only, it retains at most 50 rows containing:

- logical job name;
- `next_scheduled_run_date` as a **server-local wall-clock** `DateTime` with `DateTimeKind.Unspecified`;
- a current running flag derived from `start_execution_date` / `stop_execution_date`.

The query uses `msdb.dbo.sysjobactivity` and the latest activity `session_id`. It intentionally does not use `sysjobschedules` / `sysschedules`, collect recurrence definitions, or convert the server-local next-run value to UTC.

## Why lateness remains disabled

The collected next-run timestamp is evidence, not a canonical UTC expected-start contract. The snapshot does not yet carry a reliable server time-zone identity or recurrence/expected-run policy. `AgentReliabilityProjection` therefore continues to call the B400 reliability functions with zero lateness and keeps `ScheduleLatenessEvaluated = false`; the UI explicitly says lateness is not evaluated rather than substituting a fake value.

## UI wiring

`/jobs` now shows bounded current Agent activity per server alongside the existing recent run-history reliability evidence:

- next scheduled run rendered as server-local time;
- running / not-running status from the current Agent activity session;
- explicit evidence-only interpretation;
- no Late / On-time badge or UTC conversion.

The same change hardens aggregate truthfulness: Enabled, Failed Last Run, Run-History Risk and current Agent activity summary states no longer become green merely because missing evidence produced zero observed rows.

## Least privilege

`scripts/sql/monitored_sql_least_privilege.sql` adds only:

`GRANT SELECT ON dbo.sysjobactivity TO MonitorObserverMsdbRole;`

No SQLAgent user/reader/operator role, EXECUTE permission, schedule mutation, job-step command access, proxy access or credential access is granted.
