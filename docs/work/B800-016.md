# B800-016 — Safe aggregate-to-server drill-downs

**Umbrella:** #287  
**Branch:** `agent/b800-functional-screen-wiring`  
**PR:** #288  
**State:** IMPLEMENTED / EXACT-HEAD VALIDATION PENDING

## Objective

Ensure aggregate health modules provide a safe path back to the server-level evidence that explains their numbers, while preserving the browser GET cache-only boundary.

## Result

Database Health, Backups, SQL Agent and Storage already expose `ServerDetails` drill-down links for each server row. The pages also render the shared `_HealthSourceBadge`, retain explicit unavailable states and contain no monitored-SQL execution surface.

`tests/Monitor.Web.Tests/B800CrossPageEvidenceConsistencyTests.cs` now locks this behavior by requiring:

- a `ServerDetails` action link with the server id;
- the shared source/freshness badge;
- no `SqlConnection` or inline `SELECT` surface in the Razor views;
- explicit `Not collected` language where evidence is absent.

## Safety boundary

No route, authorization policy, collector, credential, production IIS/SQL state or RC.61 state is changed. This task closes the B800 integration contract around already-wired cache-only drill-downs.
