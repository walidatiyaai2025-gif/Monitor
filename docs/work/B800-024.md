# B800-024 — HTML mutation PRG and feedback contracts

**Umbrella:** #287  
**Branch:** `agent/b800-functional-screen-wiring`  
**PR:** #288  
**State:** IMPLEMENTED / EXACT-HEAD VALIDATION PENDING

## Objective

Lock the existing post/redirect/get feedback behavior for operator-facing HTML mutations without hiding genuine conflict, not-found or validation outcomes behind a success redirect.

## Regression contract

`tests/Monitor.Web.Tests/B800PrgFeedbackContractTests.cs` verifies:

- manual snapshot refresh stores bounded TempData feedback and redirects back to Server Details after a handled result while registration-not-found remains an explicit 404;
- incident state transitions redirect only after an applied change and preserve explicit conflict responses when the state changed or the transition is invalid;
- collaboration resolve/reopen workflows retain success/error feedback and incident-detail redirects;
- operational backup/restore returns to Settings with feedback while exact `RESTORE` confirmation rejection remains audited and explicit;
- governance and enterprise mutations retain audited feedback redirects;
- Connection Lab uses PRG after successful mutations while validation/test failures stay on the form with ModelState rather than being disguised as success.

## Safety boundary

Regression coverage only. No mutation behavior, authorization policy, monitored-SQL collection, production IIS/SQL state or RC.61 state is changed by this task.

## Validation gate

Exact-head normal CI must pass after this coverage is included. Explicit conflict/not-found behavior is part of the contract and must not be weakened merely to satisfy PRG assertions.
