## Architecture

Enterprise operator state is intentionally separate from canonical server-registration and incident lifecycle records. `IOperatorMetadataStore` has InMemory, atomic File and optimistic shared-state implementations, so adding operational metadata does not create a persistence migration for existing registration/incident contracts.

The server profile contains a bounded environment classification, optional group, up to ten strict tags, an optional maintenance window and an optional alert-suppression window. Windows are explicit UTC intervals, must have end > start and cannot exceed 31 days. Suppression is operator policy metadata: it does not delete or rewrite incident evidence.

Incident metadata contains an optional bounded assignee, at most twenty bounded notes and at most twenty recommendation acknowledgment keys. Note text rejects credential/connection-shaped material. Recommendation keys are derived from the current recommendation and stale/arbitrary route keys are rejected before state mutation.

## Operator surface

`GET /enterprise` is a bounded control-plane/read surface over registration metadata, operator metadata, incidents and the existing deterministic recommendation workflow. Mutations remain protected POST actions with antiforgery and named Operator/Administrator policies.

Exports:

- `GET /reports/servers.csv` uses registration metadata + `IServerHealthSnapshotCache.Peek` only. CSV cells are quoted and spreadsheet-formula prefixes are neutralized. SQL endpoints, usernames and secret references are not exported.
- `GET /diagnostics/package` is Administrator-only and returns a bounded ZIP containing aggregate readiness/deployment/count metadata plus a redaction statement. It excludes server names/endpoints, incident evidence, operator note content, credentials, secret references, environment-variable values, provider errors and SQL text.

## RC acceptance

`EnterpriseOperatorFeaturesTests` contains one explicit acceptance test per B100-091..100, covering window semantics/bounds, metadata normalization and file restart persistence, suppression evaluation, incident owner/note bounds, recommendation acknowledgment, formula-safe zero-SQL CSV, redacted bounded diagnostics and reflection-based route authorization/antiforgery checks.

## Guardrails

- No browser direct-to-SQL path.
- Report/diagnostic GETs do not initiate monitored-SQL collection.
- No autonomous remediation or recommendation execution.
- No credential/connection-string/operator-note content in diagnostics.
- Existing registration and incident lifecycle persistence contracts remain intact.
- Final status is not CI VERIFIED until Release `--warnaserror` build and the full test suite are Green on the PR merge-result head.
