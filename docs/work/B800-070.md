# B800-070 — Evidence-backed diagnostics projection

**Umbrella:** #287  
**State:** IMPLEMENTED / VALIDATION PENDING

## Objective

Project the bounded TempDB, transaction-log and HA evidence collected by B800-065/066/067 into operator-facing cached read models and diagnostic surfaces without converting missing inputs into zero/healthy or invoking composite B400 classifiers whose required evidence is not yet available.

## Read-model wiring

`ServerSnapshotEvidence` and `HealthModuleServerViewModel` now carry optional:

- `TempDbHealthSnapshot`;
- `TransactionLogHealthSnapshot`;
- `HaHealthSnapshot`.

`MonitorReadService` passes these fields from the shared snapshot cache into Server Details and health-module models. Browser GET/navigation remains `Peek`/cache-only and does not instantiate monitored SQL query types.

## Central projections

`AdvancedEvidenceProjection` derives only facts supported by the retained evidence.

### TempDB

- retained/total file count and truncation state;
- point-in-time used percent only when all retained files include used-byte evidence;
- size and used-percent imbalance;
- cumulative read/write latency from retained stall/operation counters;
- bounded B400 file-count guidance only when the evidence is not truncated.

TempDB growth/hour and allocation-contention evidence are not collected, so `Batch400TempDbPressure.Summarize` is not called and no composite TempDB severity is claimed.

### Transaction log

For detailed rows only:

- used percent;
- VLF band;
- normalized reuse wait;
- direct truncation-blocked flag;
- retained log-backup age fact.

Partial AG-secondary rows remain partial/null. Oldest-active-transaction age, growth/hour and policy-backed backup threshold are missing, so `Batch400TransactionLogHealth.Summarize` and composite transaction-log scores are not used.

### HA

- HADR enabled state;
- direct disconnected/unhealthy replica counts;
- non-synchronized and suspended database-replica counts;
- max SQL Server-reported secondary lag;
- max send/redo queues.

Quorum/vote evidence and policy-backed RPO/RTO inputs are not collected, so no quorum, failover-ready, RPO/RTO or composite `Batch400HaReadiness.Summarize` claim is made.

## Operator surfaces

- **Server Details:** TempDB, Transaction log and HA metric cards with explicit `Not collected`/`Not evaluated` wording. Direct observed risk facts may raise `Warning`; absence of a direct issue does not manufacture `Healthy` for these advanced dimensions.
- **Storage:** shared TempDB diagnostic table with source badge, bounded counts, nullable used/imbalance/latency and truncation-safe file guidance.
- **Database Health:** transaction-log and HA shared diagnostics. Tables display at most 12 retained rows per server even though collectors retain bounded sets of up to 50 log rows and 64 HA database-replica rows.
- **Fleet Intelligence:** coverage and direct-fact rollups for TempDB/log/HA evidence, log-reuse blocking, HA suspension and stale advanced evidence, with drill-down links to specialized pages.

## Stale / unavailable behavior

The existing source badge and `ServerDataSource` remain authoritative for cached freshness. Advanced evidence on a stale snapshot stays explicitly stale. Missing module evidence stays unavailable/null and is not transformed to zero. Fleet rollups separately count stale advanced-evidence servers.
