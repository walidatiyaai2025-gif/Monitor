# B800-086 — Contextual cached Memory Health export

## Objective

Add one bounded Viewer+ CSV for the already-collected Memory Health evidence without creating a second diagnostic truth model or any new monitored-SQL path.

## Implemented contract

- `GET /reports/memory-health/{registrationId:guid}.csv` resolves the selected registration through `IMonitorReadService.GetServerAsync(...)`.
- `MemoryHealthSummaryExport` consumes only `ServerDetailsViewModel.Evidence.Memory` and reuses `MemoryIntelligenceProjection.Build(...)` for pressure state, target attainment, OS headroom and dominant clerk summary.
- The CSV records evidence freshness, cached collection time, safe display label, SQL process utilization/physical memory, OS total/available/headroom memory, low-memory flags, max server memory, Total/Target Server Memory, target attainment, PLE, grants pending and dominant clerk summary.
- Missing snapshots and missing optional counters remain literal `Unavailable`; valid observed numeric zeroes remain valid evidence.
- `EnterpriseReportContract` remains authoritative for `monitor-export-v2`, row/byte/cell bounds and spreadsheet-formula safety.
- `EnterpriseSecurityPolicy` remains authoritative for secure download headers and bounded filenames.

## Discoverability

- Memory Health exposes `Memory CSV` only when the row ID parses to a non-empty GUID-backed registration.
- Demo/non-GUID rows do not receive an invalid contextual export link.
- Registered-but-unavailable targets remain eligible because the export contract must be able to communicate explicit `Unavailable` evidence.
- Reports & Diagnostics lists `Cached memory health summary` and routes operators to Memory Health for server selection.

## Safety / truth boundary

- Viewer+ / existing `Monitor.Read` policy only.
- No new collector, SQL query, SQL permission, snapshot refresh, POST mutation, tuning, remediation, failover or configuration write.
- No SQL text, query plans, credentials, connection strings, raw provider errors, client/table data or physical filesystem paths are exported.
- The dominant clerk output is the already-bounded clerk class/size summary; allocation detail is not exported.
- The export does not serialize the recommendation text and does not authorize automatic memory tuning.
- This slice does not publish/supersede RC.61 and cannot satisfy #162/#116/#111.

## Regression evidence

`B800MemoryHealthSummaryExportTests` locks:

- explicit `Unavailable` truth for missing snapshot and optional counters;
- formula-safe display/clerk values through `monitor-export-v2`;
- reuse of `MemoryIntelligenceProjection` for deterministic pressure/target facts;
- Viewer+ `Monitor.Read` authorization inheritance;
- contextual GUID route and secure filename subject;
- `IMonitorReadService.GetServerAsync(...)` cache ownership;
- Memory Health + Reports discoverability;
- absence of monitored-SQL collector/query and refresh-service dependencies from the route/export implementation.
