# B800-084 — Bounded cached Database Health summary export

## Scope

Expose the already-visible Database Health estate summary as one directly discoverable Viewer+ CSV without adding a collector, live monitored-SQL read or a new health-scoring algorithm.

## Runtime path

`GET /reports/database-health.csv`

`EnterpriseReportsController -> IMonitorReadService.GetHealthModulesAsync -> snapshot cache -> DatabaseStateProjection.Build -> DatabaseHealthExport -> EnterpriseReportContract.Csv`

The route inherits `Monitor.Read`. `GetHealthModulesAsync` peeks the existing snapshot cache and never initiates monitored-SQL collection.

## Export contract

- schema remains `monitor-export-v2`;
- export is capped at 250 cached server rows plus one coverage row, well below the shared 1000-row contract;
- the coverage row records observed/exported server counts and an explicit `Truncated=Yes/No` state;
- existing 1-MiB output, 500-character cell and spreadsheet-formula safety remain authoritative;
- each server row exposes cached source/freshness age, aggregate database online/total evidence, B300 worst observed database-state class, actionable/unknown counts and bounded aggregate state counts;
- `DatabaseStateProjection.Build(...)` is the same B300 classification owner used by the Database Health page.

## Truth boundary

A row with unavailable aggregate evidence serializes database online/total/age as `Unavailable` rather than treating placeholder zeroes as observations. Missing retained per-database detail keeps `DetailState`, worst class and detail-derived counts `Unavailable` instead of inferring Online/Healthy.

A complete cached snapshot may truthfully emit observed numeric zeroes. Stale cached rows remain visibly `LiveStale` through the existing source state.

## Redaction boundary

This estate export deliberately excludes individual logical database names even though the interactive Database Health page may show bounded retained names. It also excludes registration IDs, connection strings, credential references, SQL text, query plans, client/session identity, table data, raw provider payloads and physical filesystem paths.

## Discoverability

Reports & Diagnostics contains a direct Viewer+ `Download database health CSV` action. No server-selection or hidden route construction is required.

## Regression ownership

`tests/Monitor.Web.Tests/B800DatabaseHealthExportTests.cs` verifies:

- `monitor-export-v2` and spreadsheet-formula protection;
- B300 projection parity and absence of individual database names;
- explicit unavailable truth instead of placeholder zeroes;
- deterministic 250-server bound plus coverage/truncation disclosure;
- Viewer/Read authorization and central bounded filename policy;
- cache-only `GetHealthModulesAsync` / `cache.Peek(...)` source boundary;
- absence of SQL collector/query, `SqlConnection` and `physical_name` dependencies from the route/export path.

## Production boundary

B800-084 is read-only reporting over existing cached evidence. It does not publish or supersede selected RC.61, dispatch durable promotion, mutate real IIS/SQL, execute remediation or satisfy #162/#116/#111. Issue #287 remains open for B800-085+ after this slice merges.
