# B800-084 — bounded Server Intelligence report selection

## Objective

Complete the operator workflow for the B800-083 contextual Server Intelligence CSV without introducing a new evidence model or monitored-SQL path. The existing export endpoint was functional, but Reports & Diagnostics only sent the operator to the generic Servers page and did not provide a direct bounded registration selector.

## Implemented contract

- Reports & Diagnostics now loads a bounded first page of at most 50 servers through `IMonitorReadService.GetServersPageAsync(0, 50, ...)`.
- Only GUID-backed registered-server rows are offered as export targets; development/demo identities are not sent to the GUID report route.
- `GET /reports/server-intelligence.csv?registrationId=...` is a selection-route alias that delegates to the existing B800-083 `ServerIntelligence(...)` action.
- The existing export owner remains unchanged: selected-server resolution uses `IMonitorReadService.GetServerAsync`, then `ServerIntelligenceExport.Build(...)` reuses `ServerIntelligenceProjection` and `monitor-export-v2`.
- The selector states when only the first bounded server page is shown and retains the normal Servers workflow for the full estate.

## Truth and safety boundary

- Opening Reports & Diagnostics remains cache/control-plane only. `MonitorReadService` resolves the bounded selector and selected server through snapshot-cache `Peek` reads; no browser GET starts collection.
- No new SQL query, collector dependency, snapshot refresh, mutation, remediation or notification path is introduced.
- Missing selected-server snapshot evidence keeps the B800-083 explicit `Unavailable` semantics.
- Existing Viewer+ `Monitor.Read` authorization, secure download headers, CSV formula safety, size/cell bounds and redaction contract are reused.
- This slice does not publish/supersede RC.61 and does not satisfy or mutate #162/#116/#111 production acceptance.

## Regression evidence

`B800ServerIntelligenceSelectionTests` locks:

- Viewer policy inheritance;
- the 50-row server-selection bound;
- GUID-only export target selection;
- the selection route delegating to the existing Server Intelligence export action;
- report-center form wiring;
- cache `Peek` ownership and absence of monitored-SQL collector / refresh dependencies from the GET workflow.
