# B800-084 — Bounded cached Database Health summary export

## Scope

Expose one selected server's already-cached database-health evidence as a Viewer+ summary CSV without exporting retained database names, widening collection, or creating a monitored-SQL browser path.

## Runtime path

`GET /reports/database-health/{registrationId:guid}.csv`

`EnterpriseReportsController -> IMonitorReadService.GetServerAsync -> cached ServerDetailsViewModel -> DatabaseStateProjection.Build -> DatabaseHealthSummaryExport -> EnterpriseReportContract.Csv`

The route inherits `Monitor.Read`. `IMonitorReadService.GetServerAsync` resolves the selected enabled registration and peeks the existing snapshot cache. The GET does not invoke a monitored-SQL query, collector, refresh, or mutation path.

## Export contract

- schema remains `monitor-export-v2`;
- existing row/byte/cell bounds and CSV formula-safety apply;
- central secure-download headers and bounded filename policy apply;
- the selected server display label is included as formula-safe context, but registration ID is not serialized;
- cached aggregate online/total plus restoring/recovering/recovery-pending/suspect/emergency/offline-or-other counters are emitted only when the corresponding evidence exists;
- retained-state summary reuses `DatabaseStateProjection.Build(detail)` and emits only availability, retained-row count, worst-observed class, actionable count and unknown count;
- retained database names/states are deliberately not serialized by this summary export.

## Truth boundary

A registered target with no usable cached snapshot emits `Unavailable` for snapshot-derived values even though the unavailable `ServerCard` placeholder carries zero database counts for UI shape compatibility. Those placeholder zeroes are never promoted into observed database measurements.

Aggregate database detail and retained per-database rows are separate evidence dimensions. If aggregate detail exists but the retained row list is absent/empty, aggregate counters remain available while retained-state rows remain `Unavailable`; the export does not reconstruct or guess per-database states from aggregate counts. A complete cached snapshot may truthfully emit observed numeric zeroes. Fresh and stale cache states remain explicit.

## Sensitive-data boundary

The export does not serialize database names, registration IDs, credentials, connection strings, SQL text, query plans, client/session identity, table data, raw provider errors, physical filesystem paths, HADR endpoint details, or job command text. No remediation, refresh, failover, maintenance action, configuration write, or SQL execution is available from the route.

## Discoverability

Reports & Diagnostics contains a contextual Database Health summary card and sends the operator through the existing Servers selection workflow before the registration-scoped export is used.

## Regression ownership

`tests/Monitor.Web.Tests/B800DatabaseHealthSummaryExportTests.cs` verifies:

- explicit `Unavailable` behavior and no synthetic zero for unavailable registrations;
- aggregate evidence may remain available independently from retained-state evidence;
- projection parity with `DatabaseStateProjection` for retained summary values;
- retained database names are absent from the CSV;
- Viewer/Read authorization, bounded filename behavior, and Reports discoverability;
- controller/export source boundaries contain no monitored-SQL query or collector dependency and the selected-server read path remains cache-backed.
