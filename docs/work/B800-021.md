# B800-021 — Protected POST workflow matrix

## Objective

Turn the existing mutation safety convention into an assembly-wide regression contract across MVC controllers rather than relying on manual review of individual forms.

## Contract

`tests/Monitor.Web.Tests/B800WorkflowSafetyMatrixTests.cs` enumerates controller actions by reflection and requires:

- every `HttpPost` action to be covered by `ValidateAntiForgeryToken` at action or controller level;
- every `HttpPost` action to have an authorization boundary or an explicit `AllowAnonymous` declaration;
- operational POST actions outside `AccountController` to inherit or declare at least one named authorization policy;
- GET actions to remain distinct from POST mutation endpoints and not carry antiforgery mutation metadata.

This creates a fail-fast regression whenever a future controller adds a mutation without the repository's established POST + antiforgery + named-policy contract.

## Safety boundary

Test/documentation only. No route, authorization policy, runtime behavior, monitored-SQL collection, credential, production IIS/SQL state, or RC.61 state is changed.

## Validation gate

Exact-head normal CI must prove the current controller set satisfies the matrix. Any failure is treated as a real workflow-boundary discrepancy to inspect, not bypassed by weakening the assertion without evidence.
