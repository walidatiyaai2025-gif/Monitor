# B800-094 — advanced evidence responsive/accessibility hardening

## Objective

Continue B800-091..100 final acceptance by fixing an accessibility gap introduced on the newer B800 advanced-evidence surfaces without repeating the generic BATCH-700 UI foundation. Preserve the existing responsive horizontal-scroll pattern and evidence truth, while exposing complete ARIA table semantics and visible keyboard focus for TempDB, transaction-log and HA evidence.

## Existing behavior and gap

The B700 foundation already provides a reusable `.responsive-table` overflow contract, mobile breakpoints, reduced-motion handling and generic portal focus behavior. The B800 TempDB/transaction-log/HA partials correctly used labelled, focusable horizontal-scroll containers and `role="row"`, but those rows were exposed under `role="region"` without a `table` ancestor and their header/data spans had no `columnheader`/`cell` roles. The containers were keyboard-focusable through `tabindex="0"`, but the shared focus-visible selector did not explicitly include `.responsive-table`.

The surfaces were visually responsive, but the assistive-technology table structure was incomplete.

## Scope

- Change the three B800 advanced-evidence scroll tables to `role="table"` while preserving their existing accessible names and `tabindex="0"` keyboard reachability.
- Add `role="columnheader"` to every seven-column header cell.
- Add `role="cell"` to TempDB, transaction-log and HA row values, including the TempDB source badge container.
- Preserve the existing `.responsive-table` horizontal overflow and 680px minimum row-width contract so narrow screens continue to scroll rather than compress evidence into unreadable columns.
- Add `.responsive-table:focus-visible` to the existing portal focus-outline group through a guarded exact-match CSS edit.
- Add acceptance coverage that locks ARIA table/row/header/cell structure, labelled focusable tables, responsive overflow, visible keyboard focus, mobile/reduced-motion contracts and unchanged evidence truth/collection boundaries.

## Safety / truth boundary

- UI semantics/CSS plus tests/documentation only.
- No controller, route, authorization, service, projection formula, collector, query, cache or permission change.
- No evidence value, unavailable/not-evaluated wording, truncation behavior or row bound changes.
- No monitored-SQL access, refresh, mutation, remediation, tuning, failover or maintenance path.
- No RC.61 publication/selection change and no implication for `#162 -> #116 -> #111` production acceptance.
