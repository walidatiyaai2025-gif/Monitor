# B800-089 — bounded cached Performance Health estate export

## Objective

Extend the B800-081..090 reports tranche with one Viewer+ estate-wide CSV for the Performance Health evidence that is already collected and rendered by Monitor. The export must remain registration/control-plane + snapshot-cache only and must not create a browser-to-monitored-SQL path.

## Implemented scope

- Add `GET /reports/performance-health.csv` under the existing `Monitor.Read` policy.
- Read enabled registrations and `IServerHealthSnapshotCache.Peek(...)` only.
- Export cached snapshot freshness/time plus current aggregate `ActiveRequests`, `RunnableTasks`, and `PendingIoRequests`.
- Reuse `WaitIntelligenceProjection.Build(performance, uptime, 1)` for the anonymous highest existing B400 wait signal instead of creating a second wait-scoring model.
- Export only the top wait category, score, severity, normalized wait rate, share and signal percentages.
- Deliberately exclude wait type, wait fingerprint, registration ID and other per-wait identifiers.
- Preserve explicit `Unavailable` when snapshot/performance/wait evidence is missing or cache reading fails.
- Preserve legitimate observed numeric zeroes for workload aggregates.
- Reuse `monitor-export-v2`, existing row/byte/cell bounds, formula safety and secure download headers.
- Add global Reports & Diagnostics discoverability and focused regression coverage.

## Truth boundary

The wait metrics are the existing B400 projection over cumulative `sys.dm_os_wait_stats` evidence normalized by SQL Server uptime. They are not interval deltas or persisted wait history. When wait rows or valid uptime are unavailable, the export reports wait evidence as `Unavailable` and does not infer a healthy/zero wait state.

The export intentionally does not disclose the concrete wait type or fingerprint. The category and existing deterministic score/severity are sufficient for estate-level prioritization while keeping the report redacted.

## Safety boundary

- Existing Viewer+ `Monitor.Read` policy only.
- Registration/control-plane + snapshot-cache reads only.
- No monitored-SQL query, collector, permission or refresh change.
- No SQL text, query plans, client/session identity, credentials, connection strings, raw provider errors or filesystem paths.
- No wait reset, tuning, remediation, failover, maintenance execution or configuration write.
- No RC.61 publication/selection change and no implication for `#162 -> #116 -> #111` production acceptance.
