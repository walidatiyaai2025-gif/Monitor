# B800-075 — Persisted incident repository read specialization

## Scope

B800-074 introduced `IHealthIncidentRepository.Read(...)` and moved Alerts plus Fleet/Maintenance operator reads onto the bounded repository query contract. B800-075 removes the compatibility-fallback dependency from the production persisted/decorated repositories without changing incident persistence format or mutation semantics.

## Implementation

- `FileHealthIncidentRepository.Read(...)` projects directly from the repository's already-loaded `_items.Values` under the existing `_gate` lock.
- `SharedHealthIncidentRepository.Read(...)` reads the existing `monitor:incidents:v1` document once through `ReadState()` and projects the query from that validated in-memory state.
- `TelemetryHealthIncidentRepository.Read(...)` forwards to `inner.Read(...)`.
- Telemetry active-incident observation uses `Read(new IncidentRepositoryQuery(ExcludeResolved: true, Limit: 1)).TotalMatched` instead of `GetAll().Count(...)`.
- `GetAll()` remains available for explicit full-state workflows such as operational backup/export.

## Truth boundary

Shared incidents still live in one bounded/versioned JSON document. B800-075 removes the interface `GetAll()` fallback from the Shared repository's operator query path, but it does **not** make the underlying shared-state provider row-queryable or server-query-bounded. A Shared `Read(...)` still deserializes and validates that one incident document before applying the bounded query projection.

File persistence similarly remains whole-file durable state loaded into the repository at construction; native `Read(...)` avoids the extra full ordered `GetAll()` materialization/copy but does not claim disk-level indexed querying.

## Safety

- No monitored-SQL query or permission change.
- No browser-triggered collection/refresh.
- No incident mutation semantics change.
- No persistence schema/version change.
- No notification, remediation or maintenance execution.
- No RC.61 publication or `#162 -> #116 -> #111` production-boundary change.

## Regression ownership

`B800PersistedIncidentReadTests` proves:

1. File, Shared and Telemetry production repository classes own/implement the `Read` contract rather than inheriting only the interface fallback.
2. File native reads preserve exact summary/filter/paging semantics against durable repository state.
3. Shared native reads preserve exact bounded semantics while state remains one `monitor:incidents:v1` document.
4. Telemetry forwarding/observation succeeds when `GetAll()` throws, proving its query/observation path uses `Read(...)`.
