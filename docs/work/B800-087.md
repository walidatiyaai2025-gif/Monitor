# B800-087 — Bounded cached Backup Health estate summary export

## Scope

Expose enabled registrations' already-cached full-backup aggregate evidence as a Viewer+ estate CSV without exporting database names, widening snapshot collection, or claiming recovery-point compliance that the current evidence cannot support.

## Runtime path

`GET /reports/backup-health.csv`

`EnterpriseReportsController -> IEnterpriseReportingService.BackupHealth -> enabled registrations + IServerHealthSnapshotCache.Peek -> BackupHealthSummaryExport -> EnterpriseReportContract.Csv`

The route inherits `Monitor.Read`. It reads registration/control-plane state plus the existing snapshot cache only. A cache read failure is represented as an unavailable row for that enabled registration; the browser GET does not invoke a monitored-SQL query, collector, refresh, or mutation path.

## Export contract

- schema remains `monitor-export-v2`;
- existing 1000-row / 1-MiB / 500-character-cell bounds and CSV formula-safety apply;
- central secure-download headers and bounded filename policy apply;
- enabled registrations are emitted in deterministic display-name/ID order;
- each row contains only the server display label, snapshot state, collected timestamp, observed `BackedUpLast24Hours`, observed `MissingFullBackupLast24Hours`, latest observed full-backup timestamp and compliance-state marker;
- no database name or registration ID is serialized by this export.

## Truth boundary

Missing cache evidence, cache-read failure, or an absent `BackupHealthSnapshot` emits `Unavailable` for the corresponding snapshot-derived values. Placeholder zeroes are never created for unavailable evidence.

A complete cached `BackupHealthSnapshot` may truthfully emit observed numeric zeroes. Freshness is preserved from the cache entry rather than inferred from backup counts.

The current snapshot contains only aggregate full-backup coverage and latest full-backup time. It does not contain the per-database recovery model, per-database full/log backup timestamps, or governed recent-backup facts required to evaluate `Batch300BackupCompliance`. Therefore a row with available aggregate backup evidence emits `ComplianceState=NotEvaluated`; unavailable aggregate evidence emits `ComplianceState=Unavailable`. The export does not label any server Compliant/NonCompliant.

## Sensitive-data boundary

The export excludes database names, registration IDs, credentials, connection strings, SQL text, query plans, client/session identity, table data, raw provider errors, physical filesystem paths, backup file paths, job commands, and recovery media details. No remediation, restore, backup execution, refresh, maintenance action, configuration write, or SQL execution is available from the route.

## Discoverability

Reports & Diagnostics contains a global Backup Health summary card because the export is estate-wide. The card explicitly states that the source is registration + snapshot cache, database names are excluded, and RPO compliance remains `NotEvaluated`.

## Regression ownership

`tests/Monitor.Web.Tests/B800BackupHealthSummaryExportTests.cs` verifies:

- unavailable evidence remains `Unavailable` and is never converted to zero/healthy;
- observed aggregate counts/timestamps serialize exactly while compliance remains `NotEvaluated`;
- legitimately observed zeroes remain numeric zeroes;
- server labels retain shared CSV formula protection;
- Viewer/Read authorization and secure bounded filename behavior;
- service reads enabled registrations through `cache.Peek(...)`, handles `SnapshotCollectionException` fail-explicit, and does not depend on a monitored-SQL query, collector or refresh service;
- export shape contains no database-name or registration-ID field;
- Reports discoverability communicates the non-evaluated RPO boundary.
