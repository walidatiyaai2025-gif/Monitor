# B800-022 — Razor POST form to endpoint wiring

**Umbrella:** #287  
**Branch:** `agent/b800-functional-screen-wiring`  
**PR:** #288  
**State:** IMPLEMENTED / EXACT-HEAD VALIDATION PENDING

## Objective

Prevent visible mutation controls from drifting away from their MVC endpoints. A rendered button is not functionally wired unless its Razor form resolves to a real POST action.

## Contract

`tests/Monitor.Web.Tests/B800RazorPostWiringTests.cs` scans non-Shared Razor views and, for each tag-helper form that declares `method="post"` plus `asp-action`:

- resolves the explicit `asp-controller` or the view-directory controller by convention;
- requires the controller type to exist;
- requires the named action method to exist;
- requires at least one matching method to carry `HttpPost`;
- requires a meaningful minimum number of visible POST forms to be covered so the test cannot silently pass after accidental discovery breakage.

The assembly-wide B800-021 test separately enforces antiforgery and authorization on the resolved POST action set.

## Safety boundary

Regression coverage only. No runtime route, form markup, controller behavior, authorization rule, monitored-SQL collection, production IIS/SQL state, or RC.61 state is changed.
