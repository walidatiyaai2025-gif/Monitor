# B800-023 — Bounded GET filters and paging

**Umbrella:** #287  
**Branch:** `agent/b800-functional-screen-wiring`  
**PR:** #288  
**State:** IMPLEMENTED / EXACT-HEAD VALIDATION PENDING

## Objective

Lock the read-only navigation contract for the visible bounded lists so filters and page-size selections survive paging while every input remains bounded before projection.

## Regression contract

`tests/Monitor.Web.Tests/B800BoundedGetNavigationTests.cs` verifies:

- Alerts bounds offset/page size, normalizes rule IDs and carries status, severity, rule ID and limit through Previous/Next links;
- Servers bounds offset/page size inside `MonitorReadService` before `Skip/Take`, and page links preserve the bounded limit;
- History bounds offset/page size, resets offset when a new window is applied, and preserves window/limit across Previous/Next navigation;
- Reports stays read-only and routes contextual history export through an explicit server selection rather than starting collection or an unscoped mutation.

## Safety boundary

Test/documentation only. No GET route begins monitored-SQL collection, no POST or authorization boundary is changed, and no production IIS/SQL or RC.61 state is touched.

## Validation gate

Exact-head normal CI must pass after this test is included. Any mismatch should be reviewed as a navigation-contract regression rather than hidden by loosening bounds or silently dropping filters.
