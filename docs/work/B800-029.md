# B800-029 — Enterprise metadata and incident role wiring

**Umbrella:** #287  
**Branch:** `agent/b800-functional-screen-wiring`  
**PR:** #288

## Objective

Lock the Enterprise Operations control-plane role boundary so server metadata/maintenance/suppression changes remain Administrator-only while incident collaboration remains Operator/Administrator, with Viewer access staying read-only.

## Regression contract

`tests/Monitor.Web.Tests/B800EnterpriseOperationsRoleTests.cs` verifies:

- `EnterpriseOperationsController` remains readable under `MonitorPolicies.Read`;
- server metadata updates use `MonitorPolicies.Manage`, POST and antiforgery;
- incident assignment, operator notes and recommendation acknowledgement use `MonitorPolicies.Operate`, POST and antiforgery;
- the Razor server-metadata edit surface is rendered only under the Administrator `canManage` gate;
- incident owner/note/recommendation mutation controls are rendered only under the Operator/Administrator `canOperate` gate;
- GET filters remain read-only over Monitor-owned metadata/cached evidence;
- success/error feedback and audit wiring remain present;
- no browser SQL execution surface is introduced.

## Safety boundary

No authorization capability is broadened, no metadata persistence semantics are changed, no monitored-SQL query is added, and no production IIS/SQL or RC.61 state is touched. This task adds regression coverage around the existing role-aware Enterprise Operations surface.

Exact-head normal CI must pass before this slice is marked verified.
