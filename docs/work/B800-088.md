# B800-088 — Bounded cached SQL Agent Health estate export

## Scope

Expose enabled registrations' already-cached SQL Agent aggregate, bounded recent reliability and current activity evidence as a Viewer+ estate CSV without exporting job identity/ownership or enabling schedule-lateness claims that the current snapshot cannot support.

## Runtime path

`GET /reports/sql-agent-health.csv`

`EnterpriseReportsController -> IEnterpriseReportingService.SqlAgentHealth -> enabled registrations + IServerHealthSnapshotCache.Peek -> AgentReliabilityProjection.Build(..., 1) -> SqlAgentHealthSummaryExport -> EnterpriseReportContract.Csv`

The route inherits `Monitor.Read`. It reads registration/control-plane state plus the existing snapshot cache only. A cache read failure is represented as an unavailable row for that enabled registration. The browser GET does not invoke a monitored-SQL query, collector, refresh or mutation path.

## Export contract

- schema remains `monitor-export-v2`;
- existing 1000-row / 1-MiB / 500-character-cell bounds and CSV formula-safety apply;
- central secure-download headers and bounded filename policy apply;
- enabled registrations are emitted in deterministic display-name/ID order;
- each row contains server display label, snapshot state/collected timestamp, aggregate total/enabled/failed-last-run counts, explicit run-history availability, the anonymous highest existing B400 reliability score/severity/success-rate/failure-streak/P95-duration/duration-regression/alert/runs-evaluated summary, current activity availability/count/running count and schedule-lateness state;
- job names, owners and registration IDs are not serialized.

## Truth boundary

Missing cache evidence, cache-read failure or an absent `SqlAgentHealthSnapshot` emits `Unavailable` for snapshot-derived values. Placeholder zeroes are never created for unavailable evidence.

A complete cached SQL Agent aggregate may truthfully emit numeric zeroes for total/enabled/failed-last-run counts. Missing recent-run history does not become a zero reliability score or a healthy state. Missing current Agent activity does not become zero scheduled/running jobs.

When recent run history exists, the export reuses `AgentReliabilityProjection.Build(jobs, 1)` and therefore the same deterministic B400 reliability calculation used by the visible SQL Agent page. The selected top row is exported only as anonymous aggregate risk metrics; its job key and owner are deliberately omitted.

Current activity preserves only aggregate row/running counts. `ScheduleLatenessState=NotEvaluated` whenever current activity evidence exists because `next_scheduled_run_date` is server-local wall-clock evidence and the snapshot does not carry canonical server time-zone identity or recurrence/expected-run semantics. The export never emits Late/OnTime classification.

## Sensitive-data boundary

The export excludes job names/keys, owners, commands, step text, recurrence definitions, proxies, credentials, registration IDs, connection strings, SQL text/plans, client/session identity, table data, raw provider errors and filesystem paths. It also excludes individual next-run timestamps. No Agent execution, schedule mutation, job enable/disable, refresh, remediation or configuration write is available from the route.

## Discoverability

Reports & Diagnostics contains a global SQL Agent Health summary card because the export is estate-wide. The card explicitly states that job names/owners are excluded and schedule lateness remains `NotEvaluated`.

## Regression ownership

`tests/Monitor.Web.Tests/B800SqlAgentHealthSummaryExportTests.cs` verifies:

- unavailable evidence remains `Unavailable`, formula-safe and is never converted into zero/healthy;
- observed aggregate and anonymous top reliability metrics serialize exactly;
- legitimate aggregate zeroes remain numeric zeroes while missing history/activity stay unavailable;
- schedule lateness remains `NotEvaluated` and never becomes Late/OnTime;
- Viewer/Read authorization and secure bounded filename behavior;
- service reads enabled registrations through `cache.Peek(...)`, reuses `AgentReliabilityProjection.Build(jobs, 1)`, handles `SnapshotCollectionException` fail-explicit and does not depend on a monitored-SQL query/collector/refresh path;
- export shape contains no job key, owner, registration ID or individual next-run field;
- Reports discoverability communicates the redaction and non-evaluated schedule boundary.
