# B800-076 — Fleet operator-policy evidence availability

## Goal

Keep Fleet Intelligence renderable when operator metadata is corrupt or shared-state metadata reads are unavailable, without converting unavailable policy evidence into plausible defaults.

## Contract

- Reuse `OperatorPolicyReadService`, `ServerOperatorPolicyState`, and `IncidentOperatorPolicyState`; do not create a parallel availability model.
- Enabled registrations and snapshot-cache `Peek` evidence remain readable when operator metadata is unavailable.
- Environment/group/tag buckets include only servers whose `ServerOperatorPolicyState.PolicyReadable` is true.
- Fleet maintenance/suppression totals are withheld in the UI whenever server policy evidence is incomplete; an unavailable server policy is not presented as `Unspecified`, `Unassigned`, unsuppressed, or zero-maintenance evidence.
- Active incident hot-spots and Fleet decision support require both complete bounded incident evidence and readable incident/server operator-policy states for the decision population.
- A readable incident with `Assignee == null` remains legitimate unassigned evidence. A failed metadata read is a distinct unavailable state and blocks routing/correlation rather than being converted to `null` assignee.
- No monitored-SQL collection, notification, mutation, paging, remediation, or new browser-to-monitored-SQL GET path is introduced.

## Runtime coverage

`B800FleetOperatorPolicyAvailabilityTests` proves:

1. server metadata failure does not throw Fleet read and base cache availability remains visible;
2. unreadable server policy does not create environment/group/tag or maintenance/suppression facts;
3. incident metadata failure withholds rule hot-spots and decision support;
4. readable `null` assignee remains valid and allows decision support;
5. Fleet continues to use cache `Peek` only.

`B800FleetDecisionSupportSurfaceTests` pins the fail-closed service wiring and explicit unavailable UI copy.
