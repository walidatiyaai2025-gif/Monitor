# B800-090 — bounded cached Storage Health estate export

## Objective

Close the B800-081..090 reports/exports tranche with one final evidence-backed Viewer+ estate CSV for Storage Health. Reuse the allocation and B400 logical-file I/O truth already rendered by Monitor; do not widen collection or invent disk-capacity, interval-rate or file-identity claims.

## Implemented scope

- Add Viewer+ `GET /reports/storage-health.csv` under the existing `Monitor.Read` policy.
- Read enabled registrations plus `IServerHealthSnapshotCache.Peek(...)` only.
- Export cached snapshot freshness/time and aggregate database allocation bytes: total, data and log.
- Keep allocation evidence independent from logical-file I/O evidence so missing uptime/I/O cannot erase observed allocation facts.
- Reuse `IoLatencyProjection.Build(storage, uptime, 20)` for the complete currently bounded logical-file evidence and existing B400 scoring semantics.
- Export only anonymous I/O coverage and top signal: evaluated-file count, hotspot count, top score/severity, weighted latency, uptime-normalized throughput, write share and latency band.
- Deliberately exclude logical file keys, fingerprints, database/file names, registration IDs and physical filesystem paths.
- Preserve explicit `Unavailable` when snapshot/allocation/I/O evidence is missing or cache reading fails.
- Preserve legitimate observed numeric zeroes for allocation and evaluated I/O metrics.
- Reuse `monitor-export-v2`, existing row/byte/cell bounds, formula safety and secure download headers.
- Add global Reports & Diagnostics discoverability and focused regression coverage.

## Truth boundary

`TotalAllocatedBytes`, `DataAllocatedBytes` and `LogAllocatedBytes` are database allocation facts from the cached snapshot. They are **not** disk/volume capacity, free-space or growth forecasts.

Logical-file latency derives from cumulative stall/read-write counters. Throughput is normalized by SQL Server uptime through the existing `IoLatencyProjection`; it is **not** a recent interval rate or persisted trend. If bounded file-I/O counters or valid uptime are unavailable, the I/O portion of the export remains `Unavailable` and no healthy/zero state is inferred.

## Safety boundary

- Existing Viewer+ `Monitor.Read` policy only.
- Registration/control-plane + snapshot-cache reads only.
- No monitored-SQL query, collector, permission or refresh change.
- No logical/physical file mutation, growth, shrink, relocation, storage provisioning, tuning, remediation, failover, maintenance execution or configuration write.
- No credentials, connection strings, SQL text/plans, client/session identity, database/file identifiers, physical paths, raw provider errors or filesystem details.
- No RC.61 publication/selection change and no implication for `#162 -> #116 -> #111` production acceptance.
