# B800-017 — Derived intelligence freshness normalization

**Umbrella:** #287  
**Branch:** `agent/b800-functional-screen-wiring`  
**PR:** #288  
**State:** IMPLEMENTED / EXACT-HEAD VALIDATION PENDING

## Objective

Make freshness part of the derived Server Details intelligence contract so stale or unavailable snapshot state can never be presented as if it were fresh evidence.

## Implementation

- Added `ServerIntelligenceEvidenceState` with `Fresh`, `Stale`, `Unavailable`, and `Development` states.
- `ServerIntelligenceProjection` now classifies the evidence source before using snapshot evidence.
- A `RegisteredUnavailable` source fails closed even if a stale/ghost `ServerSnapshotEvidence` object is accidentally present: uptime becomes `Unknown` and composite runtime pressure is not projected.
- A live source with no snapshot evidence is normalized to `Unavailable` rather than inferring a healthy/zero state.
- Stale cached evidence may still produce deterministic decision support, but its runtime-pressure label is explicitly suffixed `stale evidence`.
- Server Details surfaces the derived evidence-state label and runtime-pressure status label; a stale otherwise-healthy runtime card is visually downgraded from healthy to warning.

## Regression coverage

`tests/Monitor.Web.Tests/ServerIntelligenceProjectionTests.cs` now covers:

- fresh cached evidence;
- stale cached evidence and explicit stale labeling;
- unavailable source with ghost evidence present;
- live source with missing snapshot evidence;
- Server Details wiring for evidence-state and runtime-pressure labels;
- preservation of the cache-only/no-synthetic-zero contract.

## Safety boundary

No monitored-SQL query, collector permission, credential boundary, mutation endpoint, production IIS/SQL state, or RC.61 state is changed. This slice only normalizes cached derived-intelligence interpretation and UI labeling.
