# B800-092 — write-surface role and antiforgery acceptance

## Objective

Continue B800-091..100 final acceptance without adding production behavior. Lock the current mutation surface so every MVC `POST` remains antiforgery-protected and authorization-bounded, with explicit role tiers for operational, advisor and administrative actions.

## Scope

- Discover every public controller action carrying `HttpPostAttribute` by reflection from the production assembly.
- Require every discovered POST action to carry `ValidateAntiForgeryTokenAttribute`.
- Permit anonymous POST only for `AccountController.Login`, while still requiring antiforgery protection.
- Require every other POST action to have an authorization boundary.
- Lock the current non-account mutation set to an explicit policy matrix:
  - `Monitor.Manage` for connection registration/credential lifecycle, server connection tests/manual snapshot refresh API, operational backup create/validate/restore, governance prune and server operator-profile administration;
  - `Monitor.Operate` for manual server refresh, incident lifecycle transitions, owner/notes and deterministic recommendation acknowledgment;
  - `Monitor.Advisor` for advisor requests.
- Keep account logout authenticated and antiforgery-protected without inventing a named policy requirement.
- Require sensitive administration controllers (`ConnectionLab`, `OperationalBackup`, `Governance`, `ServerConnections`) to remain class-level `Monitor.Manage` surfaces.
- Fail CI if a future non-account POST is added without being deliberately placed in the bounded security matrix.

## Evidence from current production surface

The current controller inventory already applies controller-side antiforgery validation to the reviewed mutation surfaces. `Program.cs` does not rely on a global MVC antiforgery filter, so preserving action-level `ValidateAntiForgeryToken` is an explicit security contract rather than a redundant convention.

Current authorization layering remains intentional: read-scoped controllers elevate individual mutation actions to `Operate`, `Advisor` or `Manage`, while administrative controllers carry class-level `Manage`. Login is the sole anonymous POST and remains antiforgery-protected.
