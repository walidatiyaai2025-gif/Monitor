# B800-082 — Bounded Maintenance decision-support export

**Umbrella:** #287  
**Scope:** reports/exports tranche  
**State:** implementation validation complete; canonical reconciliation pending

## Goal

Export one selected server/operation Maintenance Decision Support evaluation as a versioned, bounded, read-only CSV without broadening collection, maintenance authority or sensitive identity disclosure.

## Runtime contract

- Route: Viewer+ `GET /reports/maintenance-decision-support/{registrationId:guid}.csv?operation=...` under `Monitor.Read`.
- Selection identity stays in the request route only; the portable CSV deliberately excludes registration/server identity.
- Existing `EnterpriseReportContract` remains authoritative: `monitor-export-v2`, max 1000 rows / 1 MiB, max 500 chars/cell and formula-safe CSV escaping.
- `MaintenanceDecisionSupport.BuildEvidence(...)` is shared by the visible Maintenance page and report path so policy availability, bounded incident completeness and active-Critical counting cannot drift between UI and export.
- Source evidence remains `IServerRegistrationRepository`, `OperatorPolicyReadService` and `BoundedIncidentReadModel.ActiveForServer(...)` only.
- Normalized `MaintenanceOperation` is passed to the existing B400 maintenance-safety evaluation; no score/threshold/blocker algorithm is added or changed.

## Truth boundary

- Unreadable operator policy keeps environment/window evidence `Unavailable`.
- Truncated bounded incident evidence keeps active-Critical count `Unavailable`; it is never reconstructed from a partial page.
- Approval, rollback-plan, independently approved-window, replica-health and recent-backup facts remain `Unavailable` unless an explicit governed source already exists.
- `NotEvaluated`, missing inputs and unavailable decision state are exported explicitly rather than mapped to `false`, zero, Ready or Healthy.
- A complete empty bounded incident population may truthfully export zero active Critical incidents.

## Redaction / privacy boundary

The CSV never receives or serializes registration/server ID, server display name, group/tags, maintenance-window reason, incident ID/rule, assignee, credentials, connection strings, SQL text/plans, raw provider errors, monitored-SQL payloads or filesystem paths. It contains only evidence availability, normalized operation and the existing deterministic B400 decision fields when an evaluation is possible.

## UI / download safety

- The Maintenance page shows `Export current decision CSV` only after an operation is selected.
- Download filename is produced by the central `EnterpriseSecurityPolicy` subject allowlist and existing no-store/noopen/nosniff headers.
- The operation query remains inside the existing aggregate enterprise text-input budget.
- Missing/disabled registrations return 404 through the reporting service contract.

## Non-goals

- no monitored-SQL query, collector or permission change;
- no POST mutation, antiforgery change or maintenance execution;
- no notification, failover, restore, patch, configuration write or remediation authority;
- no persistence/schema change;
- no RC.61 / #162 / #116 / #111 implication.
