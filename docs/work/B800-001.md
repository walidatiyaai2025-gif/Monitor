# B800-001 — Functional wiring inventory and first operator slices

**Umbrella:** #287

## Objective

Establish the functional-completion contract for BATCH-800 and ship truth-preserving vertical slices that wire existing intelligence plus newly collected bounded evidence into operator screens without adding monitored-SQL work to browser GET navigation.

## Inventory result

The current product already has substantial runtime wiring for login, dashboard, server list/details, refresh, incidents, recommendations, reports, registration, governance, observability, settings and backup/restore. The integration gap is primarily between CI-verified intelligence/diagnostics helpers and the evidence actually collected/projected into operator pages.

The baseline cached snapshot was sufficient for:

- SQL version parsing/family/support baseline;
- edition classification;
- uptime classification;
- deterministic runtime pressure using memory + blocking + runnable-task + pending-I/O evidence.

The first collector expansion adds bounded read-only memory diagnostics: max server memory, Total/Target Server Memory, PLE, Memory Grants Pending and dominant memory-clerk class/size. B400 wait-stat, query-regression, TempDB, transaction-log, per-file I/O, detailed Agent reliability or HA projections still require separate optional evidence contracts and remain pending.

## Implemented — Server Details

- Added `ServerIntelligenceProjection` as a pure projection over `ServerDetailsViewModel`.
- Reused B300 estate-identity functions for version family/support, edition and uptime.
- Reused B300 runtime-pressure evaluation only when Memory + Blocking + Performance evidence all exist.
- Added a Server Details DBA Intelligence panel.
- Added a composite Runtime Pressure panel with explicit unavailable state when required evidence is incomplete.
- Kept existing Server Details GET cache-only; the projection has no SQL/collector/credential dependency.
- Added focused regression coverage for deterministic output, missing-evidence behavior and source-level UI wiring contract.

## Implemented — Memory Health

- Extended `MemoryHealthSnapshot` with optional/backward-compatible diagnostic fields.
- Appended seven memory diagnostic projections to the existing bounded one-statement SQL snapshot query.
- Preserved the existing two-second SQL command timeout and seven-second overall collection timeout.
- Added fail-closed validation for negative counters, malformed dominant-clerk evidence and overlong clerk identity.
- Kept SQL text, query plans, table data and configuration writes outside the collector.
- Projected full memory evidence through the shared health-module read model.
- Changed `/memory-health` to use the shared cached health-module path rather than the summarized server-card model.
- Replaced all visible Memory Health `Planned` placeholders with real evidence or explicit `Not collected` states.
- Added deterministic evidence-backed DBA recommendations; recommendations never execute tuning/configuration changes.
- Updated monitored-SQL least-privilege documentation without adding DML/DDL/sysadmin rights.
- Added collector and Memory Health regression tests.
