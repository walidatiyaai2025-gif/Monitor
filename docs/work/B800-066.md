# B800-066 — Bounded transaction-log evidence

**Umbrella:** #287  
**State:** IMPLEMENTED / VALIDATION PENDING

## Objective

Add bounded, read-only transaction-log evidence to collected server snapshots without inventing interval growth or exposing transaction/session/query identity.

## Evidence contract

For online user databases, retain at most 50 risk-prioritized rows with:

- logical database name;
- recovery model;
- total and active log size when detailed log stats are available;
- total and active VLF counts when available;
- log truncation/reuse holdup reason when available;
- age in seconds of the last transaction-log backup, computed against the SQL Server local clock;
- an explicit `HasDetailedStats` flag so partial AG-secondary evidence is never converted to zero/healthy.

The retained row count must equal `min(TotalDatabases, 50)`. `IsTruncated` is true only when more than 50 eligible online user databases exist.

## Collection path

Transaction-log evidence is optional enrichment during the existing snapshot collection/refresh path. Browser GET/`Peek` remains cache-only. Query or mapping failures leave `TransactionLogs = null` while preserving the core snapshot and other independent evidence dimensions.

## Truth boundary

This task does **not** calculate or claim:

- transaction-log growth MB/hour;
- oldest active transaction age;
- session/login/client identity;
- SQL text or query plans;
- full B400 composite transaction-log score/severity;
- backup-policy compliance.

Growth and composite scoring require additional interval/policy evidence and belong to later projection work.

## Privacy and safety

- no physical file paths;
- no transaction IDs or session IDs;
- no SQL text, query plan, client identity or table data;
- no DBCC, dynamic SQL, log shrink/grow/configuration write or autonomous remediation;
- read-only `sys.dm_db_log_stats(database_id)` projection only;
- bounded to 50 online user databases with a two-second command timeout;
- no browser-to-SQL path and no RC.61 / `#162 -> #116 -> #111` change.

## Validation

Required before merge on one exact final SHA:

- CI Green;
- Real SQL Server 2022 acceptance Green under the monitored least-privilege login;
- Windows production-candidate Green;
- branch current with `main` and no unresolved review threads.
