# B800-074 — Repository-bounded incident query contract

Umbrella: #287

## Purpose

B800-073 bounded Fleet/Maintenance decision evidence but the repository surface still exposed only `GetAll()` for list reads. B800-074 introduces an explicit bounded query contract so operator workflows no longer need a full-state API to request filtered/paged incident evidence.

## Contract

`IncidentRepositoryQuery` supports:

- optional registration scope;
- status, severity and exact rule filters;
- active-only (`ExcludeResolved`) reads;
- bounded offset `0..1,000,000`;
- bounded limit `1..1000`.

`IncidentRepositoryReadResult` returns:

- only the requested bounded page;
- exact global incident summary counts for the repository read;
- exact total matched count;
- `HasMore` derived from offset/page/total.

`IncidentRepositoryRead.Project` processes source incidents once for summary/matching and retains at most the requested `offset + limit` best-ordered matches. Ordering is deterministic: severity descending, last-seen descending, rule ID ascending, incident ID ascending.

## Operator migration

- `IncidentWorkflowService.Query` (Alerts) now calls `repository.Read(...)` instead of `repository.GetAll()` and preserves the existing global summary/filter/paging semantics.
- `BoundedIncidentReadModel` now calls `repository.Read(...)`; Fleet and Maintenance therefore consume the repository query contract and use `HasMore` to classify overflow.
- Empty Fleet/Maintenance registration scope still returns complete empty evidence without reading the store.
- InMemory production repository provides a native `Read` implementation over its concurrent state.

## Compatibility boundary

`IHealthIncidentRepository.Read` currently has a compatibility fallback implemented through `GetAll()` so existing test doubles and persisted repository implementations remain source-compatible in this slice. This fallback is **not** claimed as the final production persistence optimization.

B800-075 should specialize File, Shared and Telemetry repository implementations so production persisted paths execute `Read` natively. Shared operational state remains a single JSON document (`monitor:incidents:v1`), so even a native Shared `Read` will deserialize that bounded document before projecting a bounded result; B800 work must not claim row-level SQL querying unless the shared-state schema itself changes.

`GetAll()` remains legitimate for explicitly full-state workflows such as operational backup/export. B800-074 does not remove that contract.

## Safety

- No monitored-SQL query/permission change.
- No browser collection/refresh.
- No incident mutation semantics change.
- No notification/remediation/maintenance execution.
- No RC.61 or `#162 -> #116 -> #111` change.

## Regression ownership

- `B800BoundedIncidentReadModelTests` uses repositories whose `GetAll()` throws, proving Fleet/Maintenance bounded decision reads use `Read(...)` instead.
