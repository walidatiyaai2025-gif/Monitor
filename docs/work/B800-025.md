# B800-025 — Incident and Advisor control role wiring

**Umbrella:** #287  
**Branch:** `agent/b800-functional-screen-wiring`  
**PR:** #288  
**State:** IMPLEMENTED / EXACT-HEAD VALIDATION PENDING

## Objective

Ensure visible incident mutation and AI Advisor controls match the authorization policies already enforced by their POST endpoints. A Viewer must not be shown a control that is guaranteed to terminate in authorization failure.

## Fix

`IncidentDetails.cshtml` now renders Acknowledge and Request AI advice only inside the existing Operator/Administrator gate. Resolve-with-note and Reopen-with-reason remain inside the same gate. Viewer still receives the incident evidence, deterministic recommendation and current Advisor message as read-only content, plus an explicit read-only notice.

This aligns the UI with the existing endpoint policies:

- acknowledge/resolve/reopen: `MonitorPolicies.Operate`;
- Advisor request: `MonitorPolicies.Advisor`;
- collaboration resolve/reopen: `MonitorPolicies.Operate`;
- every endpoint remains POST + antiforgery protected.

## Regression evidence

Added `tests/Monitor.Web.Tests/B800IncidentAdvisorRoleTests.cs` to verify endpoint metadata, UI role gating, and preservation of read-only evidence without browser SQL execution.

## Safety boundary

No authorization policy was weakened, no monitored-SQL path was added, and no production IIS/SQL or RC.61 state is changed. This task removes unauthorized visible controls; it does not grant any new capability.
