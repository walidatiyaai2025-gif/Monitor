# B800-077 — Maintenance operator-policy evidence availability

## Goal

Keep Maintenance Decision Support renderable and fail-closed when server operator metadata is corrupt or shared-state metadata reads are unavailable, without treating unknown environment/window policy as safe defaults.

## Contract

- Reuse `IOperatorPolicyReadService` / `ServerOperatorPolicyState`; do not read `IOperatorMetadataStore` directly from the Maintenance controller.
- `ServerOperatorPolicyState` retains the successfully read `ServerOperatorMetadata` as an optional payload so the page can show configured-window detail without a second metadata-store read. Unavailable policy state carries no metadata payload.
- `MaintenanceDecisionEvidence.IsProduction` and `ObservedMaintenanceWindowActive` are nullable evidence.
- If environment class is unavailable, `MaintenanceDecisionSupport` returns `NotEvaluated` with `environment-class`; it never assumes non-production.
- If maintenance-window activity is unavailable, the UI renders `Not evaluated`; it never reports an inactive window from unreadable policy state.
- Existing bounded active-incident evidence remains independent. Incident overflow still yields `ActiveCriticalIncidents = null` and `NotEvaluated`.
- A configured maintenance window remains an observed scheduling fact only; it is never promoted to approved-window evidence.
- No monitored-SQL collection, maintenance execution, notification, mutation, paging, remediation, or new browser-to-monitored-SQL path is introduced.

## Runtime coverage

`B800MaintenancePolicyAvailabilityTests` proves:

1. unreadable server policy renders the controller view rather than throwing;
2. unreadable policy leaves environment/window evidence unavailable and produces `NotEvaluated` instead of a non-production decision;
3. successful policy reads retain the already-owned metadata with one server metadata-store read.

`B800MaintenanceDecisionSupportTests` pins `environment-class` as explicit missing evidence, and `B800MaintenanceDecisionSupportSurfaceTests` prevents direct metadata-store reads from returning to the controller or unavailable policy being rendered as a default.
