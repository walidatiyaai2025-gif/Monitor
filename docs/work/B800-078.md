# B800-078 — Bounded Fleet Incident Risk

**Umbrella:** #287  
**State:** canonical reconciliation complete; exact reconciled-head validation pending  
**Scope:** read-only Fleet Intelligence decision support only.

## Objective

Wire the existing deterministic `Batch300FleetRisk` contract into the visible Fleet Intelligence surface without inventing new telemetry, governance facts, or execution behavior.

The risk summary must use the same complete bounded active-incident population and readable operator-policy evidence already required by B800-073/B800-076 for Fleet routing/correlation. If either evidence boundary is incomplete, no incident risk score is produced.

## Runtime wiring

`FleetIntelligenceService.Read()` now:

1. obtains the enabled registration population;
2. reads active incidents through `BoundedIncidentReadModel.ActiveForRegistrations(...)`;
3. requires complete bounded incident evidence;
4. requires readable server and incident operator-policy evidence for every retained active incident;
5. maps `FindingSeverity.Critical` / `Warning` through the existing `Batch400FleetCorrelation.SeverityWeight(...)` contract;
6. passes rule id, last-seen time, suppression state and observed maintenance state into `Batch300FleetRisk.Summarize(...)` using `TimeProvider.GetUtcNow()`;
7. exposes the result as nullable `FleetIntelligenceSnapshot.IncidentRisk`.

No score is calculated from a partial incident set or unreadable suppression/maintenance policy state.

## UI behavior

Fleet Intelligence adds a read-only **Bounded active-incident risk** panel showing:

- score / 100;
- B300 risk level;
- actionable incident count;
- suppressed incident count;
- deterministic bounded top rule keys.

The panel explicitly states that it is decision support only and performs no notification, mutation, or remediation.

When incident evidence overflows the bounded decision-read limit, or required incident policy metadata is unreadable, the existing fail-closed warning now explicitly includes the incident risk summary among withheld outputs.

## Truth boundary

- A complete empty active-incident population is valid evidence and may produce score `0` / `Healthy` without requiring policy reads for nonexistent incidents.
- A non-empty incident population is scored only when every retained incident has readable server + incident policy state.
- Suppression and maintenance remain observed policy facts; they only weight the existing B300 risk helper and do not authorize any action.
- Rule keys are sanitized by the existing `Batch300FleetRisk.SafeKey` path inside `Summarize`.
- No new fleet-risk algorithm or threshold is introduced in B800-078.
